# Sinopebase v0.5 — Wayfinder

Three pillars: **TLS**, **Admin UI**, **Realtime Fan-out**.

## Context

v0.4.0 is tagged (1407/0 pass, CI green). Production-ready single instance. v0.5 makes it a deployable platform.

## 1. TLS

The Bun TLS plumbing is already in `app.ts` — `this.config.tls` → `Bun.file(cert)` / `Bun.file(key)`. Needs:

- [ ] Self-signed cert generation script for local dev (`scripts/gen-cert.sh`)
- [ ] Let's Encrypt / certbot integration doc
- [ ] Integration test: start with TLS cert, hit `/api/health` over HTTPS
- [ ] Railway edge termination doc (already works, just document)

Files: `src/core/app.ts:1278-1283`, `src/core/config.ts`

## 2. Admin UI

Current: placeholder HTML. Real UI in `ui/` (Svelte 5 + Vite). Auth guard at `/_/` already wired.

- [ ] Collections page — list, view schema, create/edit/delete
- [ ] Records page — per-collection CRUD via `/rest/v1/*`
- [ ] Auth users page — list, impersonate, reset password
- [ ] Settings page — app name, SMTP, auth providers
- [ ] Navigation shell — sidebar, routing, auth state
- [ ] Browser tests via gstack

Files: `ui/` (Svelte app), `src/core/app.ts:1524-1580` (mountAdminUI)

## 3. Realtime Fan-out

Current: single-replica WebSocket works. Multi-replica needs cross-replica broadcast.

- [ ] `LISTEN sinopebase_changes` on app start (one per replica)
- [ ] `NOTIFY sinopebase_changes, '<json>'` on record mutations
- [ ] RealtimeHub dispatches NOTIFY payloads to local WebSocket clients
- [ ] Integration test: two app instances, verify cross-replica broadcast
- [ ] No NATS — YAGNI for single-tenant

Files: `src/apis/realtime.ts`, `src/core/app.ts:893-909` (realtime hub setup)

## Design Decisions (from wayfinder)

- Admin UI talks to its own REST API — same PostgREST routes the SDK uses. No double plumbing.
- TLS is config, not code — Bun TLS plumbing done, just cert provisioning + tests.
- Realtime fan-out: PG LISTEN/NOTIFY, not NATS. Sufficient for single-tenant multi-replica.
