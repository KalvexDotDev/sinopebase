## 2. Admin UI — Supabase Studio parity

All UI pages talk to the same REST API the SDK uses. Svelte 5 SPA at `/_/`.

### Pages to build

- [ ] **Table Editor** — browse `public` tables, view/edit/delete rows, filter/sort/paginate, import/export
- [ ] **Auth Users** — list/search users, sessions, MFA, OAuth links, impersonate, reset password
- [ ] **Storage** — bucket CRUD, file browser per bucket, upload/download, metadata
- [ ] **RLS Policies** — read-only per-table policy viewer (policies managed via migrations)
- [ ] **API Docs** — auto-generated from PostgREST OpenAPI, example requests, key switcher
- [ ] **Realtime** — active connections, subscriptions, message log
- [ ] **Backups** — list/create/restore/schedule (service_role)
- [ ] **Mastra AI** — agent list, chat playground, tool inspector
- [ ] **Metrics** — request rate, latency, DB pool, storage usage
- [ ] **Settings** — app config, connection status, API keys (masked), OAuth providers, SMTP
- [ ] **Logs** — request log viewer with filters, error log (dev mode)

### Architecture notes
- Every page is a consumer of the existing REST API — no new backend endpoints needed
- Auth guard at `/_/` already wired in `app.ts:1524-1580`
- RLS policies are read-only in UI — edit via migrations, not UI DDL

Files: `ui/` (Svelte app), `src/core/app.ts` (mountAdminUI)
